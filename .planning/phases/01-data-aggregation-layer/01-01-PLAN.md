The existing NasaApiClient has a `.cache/nasa/` directory created in constructor but never uses it for caching responses. Wire up file-based caching:

1. In `NasaApiClient.hpp`, add to `NasaApiConfig`:
   - `int cache_ttl_days = 30;` (per user decision: NASA updates quarterly, 30 days TTL)

2. In `NasaApiClient.cpp`, add private helper methods to the Impl struct:
   - `std::string getCachePath(const std::string& queryKey)`: Hash the ADQL query string (use std::hash) to produce a filename under `.cache/nasa/`. Return the full path.
   - `std::optional<std::string> readCache(const std::string& cachePath)`: Read file if it exists AND its modification time is within `cache_ttl_days`. Return nullopt if missing or expired.
   - `void writeCache(const std::string& cachePath, const std::string& data)`: Write response string to cache file.

3. Modify `executeQuery()`:
   - Before making the HTTP request, call `readCache()` with the ADQL-based cache path. If cache hit, parse and return cached JSON directly.
   - After successful HTTP response, call `writeCache()` to store the raw JSON response.
   - Log cache hits/misses with `LOG_DEBUG("NASA cache hit: {}", cachePath)` or `LOG_DEBUG("NASA cache miss: {}", cachePath)`.

4. Add `NasaApiClient::queryByCoords(double ra_deg, double dec_deg, double radius_arcsec)` method:
   - Builds ADQL with `CONTAINS(POINT('ICRS', ra, dec), CIRCLE('ICRS', {ra}, {dec}, {radius_deg}))=1`
   - This is needed by downstream cross-matching plans. Return `std::future<std::vector<ExoplanetData>>`.

5. Also add `st_ra, st_dec` columns to the ADQL SELECT in `buildADQL()` — these are needed for coordinate cross-matching. Add corresponding `ra_deg` and `dec_deg` fields to HostStarData (in ExoplanetData.hpp), and parse them in `parseRow()`.

Use `std::filesystem::last_write_time()` for TTL checking. Use `std::hash<std::string>` for cache key generation.
