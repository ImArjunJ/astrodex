**OecClient.hpp:**
```cpp
#pragma once
#include "data/ExoplanetData.hpp"
#include <string>
#include <vector>
#include <future>
#include <memory>

namespace astrocore {

struct OecConfig {
    // GitHub raw content base URL for OEC systems
    std::string base_url = "https://raw.githubusercontent.com/OpenExoplanetCatalogue/open_exoplanet_catalogue/master/systems/";
    int timeout_seconds = 30;
    bool use_cache = true;
    std::string cache_directory = ".cache/oec";
    int cache_ttl_days = 7;  // OEC updates frequently from community
};

class OecClient {
public:
    explicit OecClient(const OecConfig& config = {});
    ~OecClient();

    OecClient(const OecClient&) = delete;
    OecClient& operator=(const OecClient&) = delete;

    // Query by planet name — fetches XML for the system
    std::future<std::vector<ExoplanetData>> queryByName(const std::string& planetName);
    std::vector<ExoplanetData> queryByNameSync(const std::string& planetName);

    // Parse XML string into ExoplanetData records (public for testing)
    static std::vector<ExoplanetData> parseSystemXml(const std::string& xmlContent);

private:
    struct Impl;
    std::unique_ptr<Impl> m_impl;

    // Fetch XML from GitHub raw content
    std::string fetchSystemXml(const std::string& systemName);
};

}  // namespace astrocore
```

**OecClient.cpp implementation details:**

1. **Impl struct:** Same pattern as NasaApiClient — CURL handle, config, response buffer, writeCallback.

2. **Name-to-filename mapping:** OEC stores systems as `{SystemName}.xml` in the `systems/` directory. Planet names like "Kepler-442 b" map to system "Kepler-442" -> file `Kepler-442.xml`. Extract system name by removing the trailing planet letter designation (last space + single letter/digit).

3. **fetchSystemXml():**
   - Build URL: `base_url + systemName + ".xml"` (URL-encode the system name)
   - Check file cache first (`.cache/oec/{hash}.xml`) with 7-day TTL
   - If cache miss, use libcurl to fetch from GitHub raw content
   - Store raw XML in cache on success
   - Handle 404 (system not found) gracefully — return empty string

4. **parseSystemXml() — CRITICAL: Handle OEC's complex nesting:**
   - OEC XML structure: `<system>` -> `<star>` -> `<planet>` (simple case)
   - Binary systems: `<system>` -> `<binary>` -> `<star>` -> `<planet>` (circumbinary)
   - Use pugixml to load XML: `pugi::xml_document doc; doc.load_string(xmlContent.c_str());`
   - Recursively walk the XML tree looking for `<planet>` nodes at any depth
   - For each `<planet>` node, traverse UP to find parent `<star>` node for host star data

5. **Planet field parsing (defensive — check node existence before access):**
   - `name`: `planetNode.child_value("name")` — required
   - `mass`: `planetNode.child("mass")` — OEC uses Jupiter masses by default. Convert: `earth_masses = value * 317.8`. Check `type` attribute for "msini" (minimum mass indicator).
   - `radius`: `planetNode.child("radius")` — OEC uses Jupiter radii. Convert: `earth_radii = value * 11.2`
   - `period`: `planetNode.child("period")` — days
   - `semimajoraxis`: `planetNode.child("semimajoraxis")` — AU
   - `eccentricity`: `planetNode.child("eccentricity")`
   - `temperature`: `planetNode.child("temperature")` — Kelvin
   - `discoverymethod`: `planetNode.child_value("discoverymethod")`
   - `discoveryyear`: `planetNode.child("discoveryyear")`
   - Uncertainties: check `errorminus`/`errorplus` attributes on each element

6. **Host star parsing (from parent `<star>` node):**
   - `name`, `mass` (solar masses), `radius` (solar radii), `temperature` (K)
   - `metallicity`, `spectraltype`, `age` (Gyr)
   - `magV` (visual magnitude), `distance` (parsecs from `<system>` node)
   - RA/Dec from `<system>` node: `<rightascension>` (HMS format, convert to degrees) and `<declination>` (DMS format, convert to degrees)

7. **Unit conversions — CRITICAL per research pitfall:**
   - OEC masses are in Jupiter masses -> convert to Earth masses (* 317.8)
   - OEC radii are in Jupiter radii -> convert to Earth radii (* 11.2)
   - OEC star masses/radii are already in solar units (no conversion needed)
   - RA format "HH MM SS" -> degrees: `(HH + MM/60 + SS/3600) * 15`
   - Dec format "+DD MM SS" -> degrees: `DD + MM/60 + SS/3600` (sign preserved)

8. All parsed values must have `source = DataSource::OEC`.

9. Call `data.calculateDerivedValues()` after parsing each planet.

Add `src/data/OecClient.cpp` to `ASTROCORE_SOURCES` in CMakeLists.txt. Link pugixml.
